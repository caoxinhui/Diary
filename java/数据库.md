# MySQL / Redis / MongoDB 对比

### 一句话定位

三者不是竞品，是分工。

| | 定位 | 一句话 |
| --- | --- | --- |
| MySQL | 关系型数据库（OLTP） | 强一致的「账本」，存数据的最终真相 |
| Redis | 内存数据结构服务器 | 快但易失，扛流量 + 做协调，**不该当主存储** |
| MongoDB | 文档型数据库 | schema 灵活的主存储，适合结构多变的数据 |

### 核心对比

| 维度 | MySQL (InnoDB) | Redis | MongoDB (WiredTiger) |
| --- | --- | --- | --- |
| 数据模型 | 表 / 行，强 schema | KV + 8 种数据结构 | BSON 文档，schema 灵活 |
| 存储介质 | 磁盘 + Buffer Pool | 内存 | 磁盘 + 缓存，带压缩 |
| 索引 | B+ 树，聚簇索引 | 无二级索引（Hash + 跳表） | B 树，支持复合 / 多键 / 地理 / TTL |
| 事务 | 完整 ACID、MVCC、4 种隔离级别 | `MULTI` 不支持回滚，靠 Lua 保原子 | 单文档原子；多文档事务可用但代价大 |
| 关联查询 | JOIN / 外键 / 子查询完备 | 无，应用层组装 | `$lookup` 有限，通常靠反范式嵌套 |
| 持久化 | redo log + binlog，可做到不丢 | RDB + AOF（`everysec` 丢 1s） | Journal（WAL），默认 100ms 刷盘 |
| 水平扩展 | 弱，需分库分表中间件 | Cluster 16384 slot，跨 slot 操作受限 | 原生 Sharding，扩展最顺 |
| 高可用 | 主从 + MHA / MGR | Sentinel / Cluster | Replica Set 自动选主 |
| 量级参考 | 单机数千～数万 QPS | 10 万+ QPS，亚毫秒 | 万级 QPS，毫秒 |

### 怎么选

```
 涉及钱 / 库存 / 订单状态，要多行强事务 ──→ MySQL
 要多表关联统计 ────────────────────────→ MySQL
 缓存 / 分布式锁 / 限流 / 排行榜 / 会话 ─→ Redis
 字段经常变（商品属性、活动配置、画像）→ MongoDB
 日志、埋点、IoT 时序，写多读少 ────────→ MongoDB
 数据量上 TB 且要持续扩容 ──────────────→ MongoDB（分片运维成本 << MySQL 分库分表）
```

典型架构是三者配合：Redis 挡在前面做缓存，MySQL 存核心交易数据，MongoDB 存日志和半结构化数据。

### 常见的过期结论

| 说法 | 纠正 |
| --- | --- |
| Redis 是单线程 | 准确说法是**命令执行**在主线程串行；网络 IO 从 6.0 起多线程，8.0 重写后 `io-threads=8` 吞吐提升约一倍 |
| Redis 不开源 | 只有 7.4～7.8 是 SSPL/RSAL。8.0（2025-05）起追加 **AGPLv3**，重新是 OSI 认可的开源 |
| JSON / 搜索 / 布隆要装 Redis Stack | 8.0 起全部并入内核，Redis Stack 已停止维护 |
| MongoDB 没有事务 | 4.0 起副本集支持多文档 ACID，4.2 起分片集群也支持 |
| MySQL 8.0 是当前版本 | 8.0 已于 **2026-04** 停止补丁，现役 LTS 是 8.4 和 9.7 |
| 用 `SHOW SLAVE STATUS` / `CHANGE MASTER TO` | 8.4 起**直接删除**，改用 `SOURCE_*` 系列语法 |

### 面试高频追问

**Q：为什么 Redis 不能当主存储？**
内存单价高、容量受限、主从异步复制在故障切换时有丢写窗口。把它当唯一真相来源是典型架构错误。

**Q：缓存一致性怎么保证？**
Cache Aside 为主（先更 DB 再删缓存），删除失败或并发读写场景补延迟双删；要求更高就订阅 binlog（Canal）异步刷缓存。

**Q：缓存穿透 / 击穿 / 雪崩？**
穿透（查不存在的 key）用布隆过滤器或缓存空值；击穿（热点 key 过期）用互斥重建；雪崩（大量 key 同时过期）用过期时间加随机值 + 多级缓存。

**Q：分布式锁为什么不能直接 `SETNX`？**
要带唯一 value + Lua 原子释放（否则会删别人的锁），还要考虑续期（Redisson watchdog）和主从切换导致锁失效（RedLock 及其争议）。

**Q：MongoDB 和 MySQL 的 JSON 字段差在哪？**
MySQL 能存 JSON，但索引要靠生成列 + 函数索引变通，查询能力弱；MongoDB 原生支持嵌套字段索引和聚合管道。数据量小、只是存点配置用 MySQL JSON 就够了。
