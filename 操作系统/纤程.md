# 进程、线程、纤程

### 一句话区分
- **进程**：资源分配的最小单位，有独立的内存地址空间
- **线程**：CPU 调度的最小单位，共享所属进程的地址空间
- **纤程**：用户态自己调度的执行流，共享所属线程的一切，切换不进内核

三者不是并列的三种东西，而是**逐层细分、逐层变轻**的关系。

### 包含关系
```
操作系统
└── 进程 A（独立内存空间，崩溃不影响别人）
    ├── 线程 1（内核调度，共享 A 的堆/全局，独享栈）
    │   ├── 纤程 a  ┐
    │   ├── 纤程 b  ├─ 由用户态调度器轮流跑在线程 1 上
    │   └── 纤程 c  ┘
    └── 线程 2
```
往下走一层，隔离性变弱、切换变快、能创建的数量变多。

### 对比
| 维度 | 进程 | 线程 | 纤程 |
| --- | --- | --- | --- |
| 谁来调度 | OS 内核 | OS 内核 | 用户程序 / 语言运行时 |
| 调度方式 | 抢占式 | 抢占式 | 协作式（主动让出） |
| 内存空间 | 独立 | 共享进程的 | 共享线程的 |
| 切换成本 | 最高（换页表、TLB 失效） | 中（陷入内核，微秒级） | 极低（只换寄存器和栈指针，纳秒级） |
| 栈大小 | — | 默认 1~8 MB | KB 级，可动态增长 |
| 数量级 | 几十~几百 | 几百~几千 | 几万~几百万 |
| 通信 | IPC：管道、共享内存、socket | 直接读写共享变量（要加锁） | 同线程内，基本无需锁 |
| 一个挂了 | 不影响其他进程 | 整个进程挂 | 阻塞同线程所有纤程 |
| 能否用多核 | 能 | 能 | 单个线程内不能，要靠 N 个线程承载 |

### 为什么要有纤程
线程的问题出在「贵」和「等」：

1. 切换要陷入内核，还会带来 CPU 缓存失效；
2. 一个线程栈动辄几 MB，一万个线程光栈就吃掉几十 GB；
3. IO 密集场景下线程大部分时间在阻塞等待，白占着内核资源。

纤程的思路：**遇到 IO 不阻塞线程，而是主动让出**，调度器换下一个纤程上来跑，等 IO 就绪再恢复。于是一个线程就能扛住成千上万个并发任务。

### 最关键的一条：抢占式 vs 协作式
- **线程是抢占式的**：时间片用完，内核强行把你换下去，代码无感知，所以要用锁保护共享数据。
- **纤程是协作式的**：必须自己主动交出执行权。一旦某个纤程里出现死循环或**同步阻塞调用**（比如同步文件读、`Thread.sleep`），同线程上所有纤程一起卡死。

这也解释了为什么协程生态必须配套「全异步的 IO 库」——用错一个同步 API，整套并发就退化了。

### 有栈 vs 无栈
- **有栈协程**：每个纤程有自己的栈，可以在任意函数嵌套深度里 yield。如 goroutine、greenlet。
- **无栈协程**：编译器把函数改写成状态机，只能在标记点（`await`）让出。如 JS / Rust / C# 的 async。
  这就是 JS 里 async 函数「会传染」（调用方也得是 async）的根源。

### 各语言里它叫什么
| 语言 | 名字 | 类型 |
| --- | --- | --- |
| Go | goroutine + GMP 调度器 | 有栈，运行时可抢占 |
| Java | 虚拟线程 Virtual Thread（JDK 21 Loom） | 有栈 |
| Python | asyncio coroutine / gevent greenlet | 无栈 / 有栈 |
| C# | `async`/`await` + Task | 无栈 |
| Lua | coroutine | 有栈 |
| Kotlin | coroutine | 无栈（编译期 CPS 变换） |
| JS | 没有真正的纤程，只有单线程 + Event Loop；`async/await` 是无栈协程的效果 | 无栈 |

### 前端视角的类比
- 打开一个浏览器 Tab → 一个**渲染进程**（这也是为什么一个页面崩了不会带走整个浏览器）
- Tab 内的 GUI 渲染线程、JS 引擎线程、定时器线程、网络线程 → **线程**
- 一个 `async` 函数在 `await` 处挂起、微任务队列恢复它 → 最接近**纤程**的体验

注意：JS 的 Event Loop 是纤程思路的「阉割版」——只有一个执行流，靠回调/微任务切换任务，但没有独立的调用栈可保存，所以是无栈的。

### 怎么选
- **CPU 密集**（计算、加解密、图像处理）→ 多进程 / 多线程，目的是吃满多核，纤程在这里没有意义
- **IO 密集**（网络请求、数据库、文件）→ 纤程 / 协程，用极小成本撑起高并发
- **需要强隔离**（插件、沙箱、第三方代码、崩溃不能扩散）→ 进程
- 实际的高性能服务通常是组合拳：**多进程（打满核心） × 每进程多线程 × 每线程多纤程**
