### 构建期：你的代码是怎么变成镜像的

```
前端仓库                              后端仓库
 src/*.js *.vue *.ts                   src/main/java/**/*.java
   │ npm run build                        │ mvn package
   ▼                                      ▼
 dist/  index.html main.js main.css     target/app.jar（.class + 依赖）
   │                                      │
   │ Dockerfile                           │ Dockerfile
   │   FROM nginx:1.25                    │   FROM openjdk:17-jdk-slim
   │   COPY dist/ /usr/share/nginx/html   │   COPY app.jar /app.jar
   │   EXPOSE 80                          │   CMD java -jar /app.jar
   │ docker build -t my-web:v1 .          │ docker build -t my-api:v1 .
   ▼                                      ▼
镜像 my-web:v1（只读・分层）            镜像 my-api:v1（只读・分层）
  层3  你的 dist 静态文件                  层3  你的 app.jar
  层2  nginx 二进制                        层2  JDK 17
  层1  debian 精简根文件系统               层1  debian 精简根文件系统 ← 层可复用/缓存
   │                                      │
   └───────────── docker push ────────────┘
                      ▼
        镜像仓库 Registry（Harbor / DockerHub）
                      │  服务器上 docker pull && docker run
                      ▼
                  回到上面那张运行期的图
```

### 一句话对应关系（拿盖楼类比）

| 概念 | 类比 | 本质 |
| --- | --- | --- |
| 服务器 | 地皮 + 水电总量 | 唯一真正拥有 CPU / 内存 / 磁盘 / 网卡的实体 |
| 资源 | 那些水电 | 容器不「拥有」资源，只是被 cgroups 限额地借用宿主的 |
| 镜像 Image | 装修好的样板房图纸 | 只读、分层、可无限复制、能推到镜像仓库 |
| 容器 Container | 照图纸盖出来、真住了人的房子 | 宿主机上一个被 namespace 隔离的普通进程 |
| Docker Engine | 物业兼施工队 | 按图纸开工、划分水电配额、接通门牌号（端口映射） |
| nginx 容器 | 前台接待 | 把前端打包产物当静态文件下发，同时把 `/api` 反代给后端 |
| java 容器 | 后厨 | 真正在服务器上长期运行、算业务、连数据库 |

### 三个最容易搞混的点

1. **前端 JS 代码并不在服务器上「运行」。**
   它只是被 nginx 当成静态文件下发，真正执行它的是用户的浏览器。
   服务器上跑的是 nginx 进程；后端 Java 才是真的在服务器上跑的进程。

2. **镜像 ≠ 容器。**
   镜像是只读模板（类比 class），容器是它的运行实例（类比 object）。
   一个镜像可以 `docker run` 出 N 个容器；容器停掉删掉，镜像还在。

3. **容器 ≠ 虚拟机。**
   容器没有自己的内核，直接复用宿主 Linux 内核，所以启动毫秒级、开销接近裸进程；
   虚拟机要自带一整个内核和 OS，启动几十秒、每台多占几百 MB 内存。
